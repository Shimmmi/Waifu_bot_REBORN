# ТЗ: Эндгейм-экономика (Custom-подземелья, Зачарование, Респек Парагона)

Версия 0.1 — дополнение к основному ТЗ Вайфу-бот v0.2

---

## Раздел 1. Обзор изменений

Документ описывает три взаимосвязанные системы, закрывающие проблему
"золоту некуда деваться" на позднем этапе игры (60+ уровень / парагон):

1. **Custom-подземелья с аффиксами** — ежедневный процедурный контент
   с едиными для всех игроков модификаторами, гейтингом по силе
   персонажа и наградным множителем, растущим с тиром сложности.
2. **Вкладка «Зачарование»** — реролл обычных аффиксов/суффиксов
   предметов за пыль + золото, отдельно от существующей перековки
   легендарных бонусов.
3. **Респек Парагона** — платное переназначение уже выбранных
   парагон-бонусов/очков навыков.

Материалы для доводки предметов (Common→Advanced→Elite) и валюты
зачарования распределяются градиентом между Подземельем+ и Бездной
(см. Раздел 5).

## Раздел 2. Custom-подземелья

### 2.1 Концепция

После прохождения основной кампании часть подземелий каждый день
(обновление в 00:00 МСК, синхронно с найм-пулом и слотами экспедиций)
становится "особыми" — каждому монстру в них присваивается
детерминированный (по сид-значению дня) набор аффиксов/суффиксов из
существующей таблицы `monster_affixes`.

Тиры сложности: **+5, +10, +15, +20, +25**, распределены по актам и
подземельям. Набор одинаков для всех игроков в течение суток —
единый ежедневный вызов, а не персональная генерация.

### 2.2 Гейтинг доступа

Каждый тир открывается по требованию к силе персонажа (paragon level
ИЛИ средний item power экипировки — берётся максимум из двух проверок,
чтобы не блокировать игроков с сильным билдом, но малым парагоном):

| Тир | Мин. paragon level | ИЛИ мин. средний item level экипировки |
|-----|--------------------|------------------------------------------|
| +5  | 61                 | 25                                        |
| +10 | 65                 | 30                                        |
| +15 | 70                 | 35                                        |
| +20 | 75                 | 40                                        |
| +25 | 80                 | 45                                        |

Конкретные пороги — переменные БД (`custom_dungeon_tier_requirements`),
калибруются по факту после сбора телеметрии.

### 2.3 Генерация аффиксов по тиру

Правило: чем выше тир — тем больше слотов аффиксов на монстра и выше
доля поведенческих (не только статовых) аффиксов. Переиспользуется
существующая логика ограничений (`incompatible_with`,
`allowed_families`, `max_per_monster` — см. основное ТЗ, раздел
"Аффиксы и суффиксы монстров").

| Тир | Слотов аффиксов/монстр | Доля поведенческих | Множитель наград (gold/exp) | Бонус к шансу/редкости дропа |
|-----|--------------------------|---------------------|--------------------------------|-------------------------------|
| +5  | 1                        | 20%                 | ×1.3                            | +5%                            |
| +10 | 2                        | 35%                 | ×1.6                            | +10%                           |
| +15 | 2                        | 50%                 | ×2.0                            | +15%, +1 ступень редкости      |
| +20 | 3                        | 65%                 | ×2.5                            | +20%, +1 ступень редкости      |
| +25 | 3                        | 80%                 | ×3.2                            | +25%, +2 ступени редкости      |

Множители — переменные БД, вынесены отдельно для баланса.

### 2.4 Детерминированный сид

```
daily_seed = hash(date_UTC_string + "custom_dungeon")
```

Генерация набора монстр→аффиксы для каждого custom-подземелья дня
использует `daily_seed` как источник для `random.seed()` при выборе
из `monster_affixes` — гарантирует одинаковый результат у всех
игроков без хранения полного дампа комбинаций в БД (достаточно
хранить сид и параметры подземелья, аффиксы пересчитываются на лету
по тому же алгоритму на клиенте/сервере).

### 2.5 Схема БД

```sql
CREATE TABLE daily_dungeon_seeds (
    id                  SERIAL PRIMARY KEY,
    seed_date           DATE NOT NULL UNIQUE,       -- дата активации (00:00 МСК)
    daily_seed          VARCHAR(64) NOT NULL,        -- hash-строка, источник RNG
    created_at          TIMESTAMP NOT NULL DEFAULT now()
);

CREATE TABLE custom_dungeon_instances (
    id                  SERIAL PRIMARY KEY,
    seed_date           DATE NOT NULL REFERENCES daily_dungeon_seeds(seed_date),
    base_dungeon_id     INT NOT NULL REFERENCES dungeons(id),  -- какое обычное подземелье "переопределяется"
    act                 INT NOT NULL,
    tier                INT NOT NULL,                -- 5 / 10 / 15 / 20 / 25
    min_paragon_level   INT NOT NULL,
    min_avg_item_level  INT NOT NULL,
    affix_slots_per_monster INT NOT NULL,
    behavior_affix_ratio    FLOAT NOT NULL,           -- 0.0–1.0
    gold_mult           FLOAT NOT NULL,
    exp_mult            FLOAT NOT NULL,
    drop_chance_bonus_pct   FLOAT NOT NULL,
    drop_rarity_bonus_steps INT NOT NULL DEFAULT 0,
    UNIQUE (seed_date, base_dungeon_id)
);

CREATE TABLE custom_dungeon_monster_affixes (
    id                      SERIAL PRIMARY KEY,
    custom_dungeon_id       INT NOT NULL REFERENCES custom_dungeon_instances(id) ON DELETE CASCADE,
    monster_slot_index      INT NOT NULL,             -- позиция монстра в цепочке подземелья (1..N, N+1=босс)
    affix_id                INT NOT NULL REFERENCES monster_affixes(id),
    slot_order              INT NOT NULL              -- порядок применения (для stacking-логики)
);

CREATE TABLE custom_dungeon_progress (
    id                  SERIAL PRIMARY KEY,
    user_id             BIGINT NOT NULL REFERENCES users(id),
    custom_dungeon_id   INT NOT NULL REFERENCES custom_dungeon_instances(id),
    started_at          TIMESTAMP,
    completed_at        TIMESTAMP,
    status              VARCHAR(16) NOT NULL DEFAULT 'not_started', -- not_started/active/completed/failed
    last_hit_at         TIMESTAMP,                     -- для anti-spam cooldown
    UNIQUE (user_id, custom_dungeon_id)
);
```

### 2.6 Анти-спам

Отдельно от общей "скорости атаки" оружия (мин. символов в сообщении)
добавляется cooldown между засчитываемыми ударами именно в
custom-подземельях, чтобы исключить накрутку прогресса ботом на
фиксированном ежедневном сиде:

```python
CUSTOM_DUNGEON_HIT_COOLDOWN_SEC = 2  # переменная БД

def process_message_in_custom_dungeon(user_id, dungeon_progress, message):
    now = datetime.utcnow()
    if dungeon_progress.last_hit_at and \
       (now - dungeon_progress.last_hit_at).total_seconds() < CUSTOM_DUNGEON_HIT_COOLDOWN_SEC:
        return  # игнорируем удар, не в кулдауне

    if len(message.text or "") < equipped_weapon.attack_speed:
        return  # не хватает символов

    damage = calculate_damage(user_id, message)
    apply_damage_to_monster(dungeon_progress, damage)
    dungeon_progress.last_hit_at = now
    save(dungeon_progress)
```

### 2.7 UI

**Карточка в списке подземелий (`dungeons.html`, вкладка «Одиночные»):**
- Поверх обычной карточки — рамка цвета по тиру (например: +5 синяя,
  +10 фиолетовая, +15/+20 оранжевая, +25 красная с свечением) и
  числовой бейдж "+N" в углу.
- Если игрок не проходит гейтинг — карточка визуально затемнена,
  бейдж требования ("Paragon 70+") вместо кнопки «Войти».

**Модальное окно (по клику на custom-карточку, до старта боя):**
- Заголовок: название подземелья + тир.
- Список аффиксов, присутствующих в подземелье (агрегировано по всем
  монстрам, без дублей) — иконка + краткое описание, как в существующей
  системе аффиксов.
- Блок наград: множители золота/EXP, бонус к шансу/редкости дропа.
- Кнопка «Войти» (запускает бой) и «Отмена» (закрывает окно).

## Раздел 3. Вкладка «Зачарование» (Enchanting)

### 3.1 Концепция

Отдельная механика от существующей перековки легендарных бонусов.
Работает с обычными аффиксами/суффиксами предметов редкости
Rare/Epic (Common/Uncommon — не имеют смысла зачаровывать, слишком
мало аффиксов). Позволяет заменить один конкретный (выбранный
игроком) аффикс предмета на новый случайный вариант из 2–3
предложенных.

### 3.2 Источник валюты «Пыль»

Дизенчант (разбор) ненужных предметов в мастерской:

```
пыль_за_предмет = BASE_DUST[редкость] × tier_множитель(item_level)
```

| Редкость  | BASE_DUST |
|-----------|-----------|
| Common    | 1         |
| Uncommon  | 3         |
| Rare      | 8         |
| Epic      | 20        |

`tier_множитель` — совпадает с существующей таблицей тиров предметов
(тир 1 = ×1.0 ... тир 10 = ×3.0, линейно либо по шагам — переменная БД).

### 3.3 Формула стоимости реролла аффикса

```
цена_пыль  = BASE_ENCHANT_DUST[редкость] × (1 + reroll_count_on_item × 0.15)
цена_золото = BASE_ENCHANT_GOLD × item_level × act_multiplier
```

- `reroll_count_on_item` — счётчик per-item (хранится на экземпляре
  предмета, не сбрасывается), защищает от бесконечного дешёвого
  фарма идеального ролла на одном предмете.
- `BASE_ENCHANT_DUST`, `BASE_ENCHANT_GOLD`, `act_multiplier` —
  переменные БД.

При реролле: старый аффикс безвозвратно удаляется, из пула
доступных для данного типа/уровня предмета аффиксов случайно
предлагается 2–3 варианта (аналогично Diablo 4 — "Tempering"/окно
выбора), игрок подтверждает один.

### 3.4 Схема БД

```sql
CREATE TABLE user_currencies (
    user_id             BIGINT PRIMARY KEY REFERENCES users(id),
    dust                INT NOT NULL DEFAULT 0,
    abyss_shards         INT NOT NULL DEFAULT 0   -- существующая валюта Бездны, для консистентности
);

ALTER TABLE item_instances
    ADD COLUMN enchant_reroll_count INT NOT NULL DEFAULT 0;

CREATE TABLE enchant_affix_pool (
    id                  SERIAL PRIMARY KEY,
    item_type           VARCHAR(32) NOT NULL,     -- weapon/armor/ring/amulet
    affix_key           VARCHAR(64) NOT NULL,      -- напр. dmg_melee, crit_chance
    min_item_level       INT NOT NULL,
    max_item_level       INT NOT NULL,
    value_formula        VARCHAR(128) NOT NULL      -- напр. "1.0 + item_level*0.05"
);

CREATE TABLE enchant_transactions (
    id                  SERIAL PRIMARY KEY,
    user_id             BIGINT NOT NULL REFERENCES users(id),
    item_instance_id    BIGINT NOT NULL REFERENCES item_instances(id),
    old_affix_key       VARCHAR(64),
    new_affix_key       VARCHAR(64),
    dust_spent          INT NOT NULL,
    gold_spent          INT NOT NULL,
    created_at          TIMESTAMP NOT NULL DEFAULT now()
);
```

### 3.6 UI

Вкладка «Зачарование» в мастерской (соседняя с существующей
перековкой легендарных бонусов, но визуально и функционально
разделена — разный набор валют и разные предметы-цели):

- Слот выбора предмета (drag/tap из инвентаря, только Rare+/Epic).
- Список текущих аффиксов предмета, каждый с кнопкой «Заменить».
- По нажатию — модальное окно превью (см. `enchant/preview`) с 2–3
  карточками вариантов и кнопкой подтверждения.
- Счётчик "Реролл №X на этом предмете" отображается явно — прозрачность
  растущей цены важна для доверия игрока к системе.

## Раздел 4. Респек Парагона

### 4.1 Концепция

Дополнение к уже существующей системе парагон-уровней (60+, 3
бонуса на выбор за уровень, дополнительное очко навыка каждые 10
уровней). Позволяет переназначить уже выбранные бонусы/очки за
золото — постоянный, немасштабируемый по кол-ву использований синк
(в отличие от зачарования, где цена растёт per-item, здесь цена
растёт per-paragon-level и не имеет истории использований —
респекать можно многократно по одной и той же формуле).

### 4.2 Формулы стоимости

**Респек обычного парагон-бонуса (стат/ресурс):**
```
cost_gold = BASE_PARAGON_RESPEC_COST × paragon_level × (1 − ОБА × 0.001)
```

**Респек очка навыка (каждый 10-й уровень):**
```
cost_gold = BASE_PARAGON_RESPEC_COST × paragon_level × 3 × (1 − ОБА × 0.001)
```
(×3 — навык глубже завязан на билд, чем плоский стат-бонус)

`BASE_PARAGON_RESPEC_COST` — переменная БД, калибруется по данным о
среднем золоте/час на 60+ уровне.

Формула сознательно повторяет паттерн уже принятых формул (прокачка
наёмниц, стоимость лечения) — единообразие расчётов в кодовой базе.

### 4.3 Схема БД

Предполагается, что существующая система парагона уже хранит выбор
бонусов на уровне пользователя — здесь добавляется только лог и,
при необходимости, поле версии для отката:

```sql
CREATE TABLE paragon_choices (
    id                  SERIAL PRIMARY KEY,
    user_id             BIGINT NOT NULL REFERENCES users(id),
    paragon_level       INT NOT NULL,
    choice_type         VARCHAR(16) NOT NULL,   -- 'stat_bonus' / 'skill_point'
    chosen_key          VARCHAR(64) NOT NULL,   -- напр. 'str_bonus', 'skill_iron_will'
    is_active            BOOLEAN NOT NULL DEFAULT TRUE,
    UNIQUE (user_id, paragon_level, choice_type)
);

CREATE TABLE paragon_respec_log (
    id                  SERIAL PRIMARY KEY,
    user_id             BIGINT NOT NULL REFERENCES users(id),
    paragon_level       INT NOT NULL,
    choice_type         VARCHAR(16) NOT NULL,
    old_key             VARCHAR(64),
    new_key             VARCHAR(64),
    gold_spent          INT NOT NULL,
    created_at          TIMESTAMP NOT NULL DEFAULT now()
);
```

### 4.4 API-контракт

```
POST /api/paragon/respec
{
  "paragon_level": 63,
  "choice_type": "stat_bonus"
}
→ {
  "cost_gold": 48200,
  "confirm_required": true
}

POST /api/paragon/respec/confirm
{
  "paragon_level": 63,
  "choice_type": "stat_bonus",
  "new_key": "int_bonus"
}
→ { "success": true, "gold_remaining": 152340 }
```

### 4.5 UI

На странице парагона (внутри `profile.html` либо отдельной вкладки
"Совершенствование", в зависимости от текущей реализации) —
у каждого уже пройденного уровня появляется мелкая иконка "↺"
рядом с выбранным бонусом. По нажатию:

- Модальное окно с текущей ценой респека (см. формулу выше).
- Кнопка «Подтвердить» → повторный выбор из 3 вариантов (как при
  первом получении уровня).
- Кнопка «Отмена».

## Раздел 5. Градиент материалов (Подземелье+ / Бездна)

Сводная таблица источников по системам, описанным выше и в основном
ТЗ (доводка предметов Common→Advanced→Elite):

| Ресурс                                   | Подземелье+ (1–30) | Бездна |
|-------------------------------------------|----------------------|--------|
| Материал Common → Advanced                | Низкий шанс дропа    | Повышенный шанс |
| Материал Advanced → Elite                 | Недоступен           | Основной источник |
| Пыль зачарования                          | Дизенчант (везде)    | Бонусный дроп на этажах |
| Осколки перековки легендарных бонусов     | Недоступен           | Только глубокие этажи |
| Custom-подземелья (золото/EXP/дроп)       | Не пересекается — отдельная система, доступна вне зависимости от Бездны | — |

Это сохраняет доступность базовой доводки для игроков, ещё не
готовых к Бездне (решение Марины из предыдущего обсуждения), но
делает Elite-тир и продвинутые манипуляции с предметами прямой
причиной проходить именно Бездну.

## Раздел 6. Открытые вопросы перед реализацией

1. **Зависимость от легендарного бага-аудита.** Перед вводом реролла
   легендарных бонусов и системы зачарования нужно закрыть уже
   найденные баги легендарной системы (midnight-crossing,
   Fibonacci-счётчики без сброса, конфликт `consume`-флагов) — новый
   синк не должен строиться поверх нестабильного фундамента.
2. **Телеметрия.** Все `BASE_*` константы (респек, зачарование,
   множители наград custom-подземелий) требуют калибровки по
   реальным данным притока золота на 60+ уровне — в документе
   заданы формулы и относительные пропорции, но не финальные числа.
3. **Механизм парагон-выбора.** Формулы респека предполагают, что
   бонусы выбираются игроком (не выпадают случайно). Если текущая
   реализация парагона случайна — раздел 4 требует пересмотра
   (респек тогда не нужен, нужен reroll с похожей механикой на
   зачарование).
4. **Персистентность материалов Бездны.** При Celery-сбросе цикла
   Бездны (существующая задача сброса) накопленные материалы/пыль/
   осколки не должны обнуляться — обнуляется только текущий забег
   и глубина этажа.
